arches_he_data_transformation 1.1.0 Release Notes
--------------------------

### Added autopopulate-node-from-card-nodes
- Integrated the pre-existing `autopopulate-node-from-card-nodes` function into the repository.
  - Function location: `arches_he_data_transformation/functions/autopopulate_node_from_card_nodes_function.py`
  - This function auto-populates a target string node using values from other nodes in the same card, triggered on tile save, with configurable string templates, multiple mappings per graph, and an optional overwrite flag.
  - See the docstring and inline comments in the function file for usage details.
- Migration `91002_autopopulate_function_registration` registers the function idempotently in the Arches `Function` table on deployment (using `update_or_create`).
- Unit tests added in `tests/function_tests/`.
  - Test fixture `tests/fixtures/pkg/graphs/resource_models/Autopopulate_Test_Model.json` contains a minimal resource model with two cards:
    - **Person Details** – First Name (string), Last Name (string) → Full Name (string, autopopulated target)
    - **Location Details** – City (string), Country (string) → Location Summary (string, autopopulated target)
  - 9 tests covering:
    - Function registration (`test_function_is_registered`)
    - Template substitution from source nodes
    - `overwrite=False` preserves an existing target value
    - `overwrite=True` replaces an existing target value
    - `request=None` early-return guard (protects bulk-import paths)
    - Graceful handling of an empty source node value
    - Multi-rule config: the Person Details rule fires only for a Person Details tile
    - Multi-rule config: the Location Details rule fires only for a Location Details tile
    - Multi-rule config: rules for separate nodegroups are fully independent of one another
  - **Note on test approach**: the guide's standard pattern (register the function in `functions_x_graphs`, save via `Tile.save(request=...)`) is not used here because `autopopulate_nodes()` calls `tile.save()` on the same tile it processes, which would cause infinite recursion if the function were registered for that nodegroup. Tests therefore call `func.save()` directly and assert on in-memory `tile.data`. This deviation is documented in the test class docstring.
  - Run with: `python manage.py test tests.function_tests --settings="tests.test_settings_for_docker"`
